# تجربة المزامنة التلقائية

## عنوان الجهاز الحالي

في 12 أكتوبر 2026 ظهر جهاز البصمة في iVMS-4200 بالعنوان `192.168.8.130`
بدل `192.168.8.97`. نجح فحص الأحداث ودخول HR بالبيانات المحفوظة على العنوان
الجديد؛ تغيير IP لا يتطلب تغيير كلمة المرور. جميع أدوات الاتصال والمزامنة
تقرأ الآن `tools/hikvision_device.json`، وتعيد الخدمة تحميل العنوان كل دورة.
العملية القديمة تحتاج إعادة تشغيل مرة واحدة لتحميل هذا التعديل.

الملف يحتوي العنوان فقط دون كلمات مرور. يبقى HTTP على المنفذ 80 لأداة ISAPI؛
سجل iVMS يستخدم منفذ الجهاز 8000، فلا تستبدل أحدهما بالآخر. تحديث عنوان
المشروع لا يغيّر إعدادات الشبكة في الجهاز أو الراوتر ولا سجل الجهاز في iVMS.
لمنع تكرار التغيير، ثبت عنوان الجهاز بحجز DHCP في الراوتر أو بعنوان LAN ثابت
متوافق مع شبكة المكتب بعد التحقق من عدم تعارضه مع جهاز آخر.

هذه مرحلة تجربة على جهاز `192.168.8.97` الذي نجح اختبار الاتصال به. أداة Windows تقرأ أحداث الوجه والبصمة والبطاقة كل دقيقة عبر ISAPI، وترسل الحقول الضرورية إلى RPC في Supabase بحساب HR أو admin. لا يستخدم Flutter كلمة مرور الجهاز أو مفتاح service_role. لم تُشغّل الأداة على الجهاز أو قاعدة البيانات أثناء تطوير هذه المرحلة.

## أول خطوة: المعاينة

من مجلد `tools` داخل مشروع ERP، افتح `preview_hikvision_sync.cmd`. أدخل اسم مستخدم جهاز البصمة وكلمة مروره داخل نافذة الأداة. تقرأ آخر 24 ساعة بصفحات متعددة وتحفظ `build/hikvision-sync/preview.json` بدون كتابة في قاعدة البيانات. أرسل صورة سطر النتيجة فقط؛ لا ترسل كلمات المرور أو رموز الدخول.

## التفعيل بعد نجاح المعاينة

1. نفّذ `supabase/install_hikvision_sync.sql` في SQL Editor، بعد ملف ربط أرقام البصمة `install_attendance_identity.sql` الذي سبق تثبيته.
2. تأكد أن رقم الجهاز مسجل عند الموظف في HR، وأن ساعة الجهاز والمنطقة الزمنية صحيحتان.
3. افتح `tools/start_hikvision_sync.cmd` على كمبيوتر الدوام. أدخل بيانات الجهاز، ثم بريد وكلمة مرور حساب ERP له صلاحية HR أو admin. يقرأ عنوان Supabase ومفتاح التطبيق العام من `.env` الموجودة بالمشروع.
4. اترك النافذة تعمل أثناء التجربة. تظهر نتيجة كل دفعة: أحداث جديدة، أيام تغيرت، أيام محمية، أحداث غير مربوطة، وحالات غير مدعومة. `Ctrl+C` يوقفها.

تشغيل `start_hikvision_sync.cmd` يدويًا يعمل كل دقيقة ما دامت نافذته مفتوحة، ويطلب بيانات الدخول في كل تشغيل. جلسة Supabase تتجدد أثناء التشغيل وفق [وثائق جلسات Supabase](https://supabase.com/docs/guides/auth/sessions). أثبتت صورة المستخدم نجاح أول دفعة حية: 7 أحداث جديدة، يوم واحد تغير، و4 أحداث لأرقام غير مربوطة.

## التشغيل التلقائي بعد تسجيل الدخول إلى Windows

1. أغلق نافذة المزامنة اليدوية القديمة بـ `Ctrl+C` حتى لا تمنع المزامنة الجديدة من العمل.
2. افتح `tools/setup_hikvision_autostart.cmd` على كمبيوتر الدوام، باستخدام حساب Windows اليومي نفسه. أدخل بيانات الجهاز ثم بيانات حساب ERP للـHR أو admin مرة واحدة.
3. عند ظهور `SUCCESS` أغلق نافذة الإعداد. تبدأ المزامنة فورًا في الخلفية، ثم تلقائيًا بعد كل تسجيل دخول إلى Windows. لا يلزم فتح ERP أو iVMS لإبقاء الأداة تعمل؛ يلزم بقاء الكمبيوتر متصلًا بالشبكة والإنترنت.
4. بعد دقيقة افتح `tools/check_hikvision_sync_status.cmd`. نتيجة `sync_success` تؤكد آخر دفعة؛ `sync_failed` تعني مراجعة الشبكة أو بيانات الدخول. تحقق من وقت النتيجة أيضًا؛ يظهر تنبيه إذا مضى أكثر من خمس دقائق.

مهمة Windows باسم `Dimah ERP Hikvision Attendance` تعمل بالصلاحيات العادية لحساب Windows الذي شغّل الإعداد، دون طلب كلمة مرور Windows. تبدأ **بعد دخول هذا الحساب**، وليس قبل شاشة تسجيل الدخول؛ ليست خدمة Windows تعمل أثناء تسجيل الخروج. قفل الشاشة يبقيها تعمل. لا تنقل مجلد المشروع بعد الإعداد دون إعادة تشغيل الإعداد لتحديث المسار.

تُحفظ كلمات المرور مشفرة بـDPAPI في `%LOCALAPPDATA%\DimahERP\HikvisionSync\credentials.xml` وتُقيد صلاحيات المجلد بالمستخدم وSYSTEM. التشفير مرتبط بحساب Windows والكمبيوتر وفق [توثيق Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/export-clixml). لا تُحفظ كلمات المرور في المشروع أو سجل الحالة. يتطلب الإعداد مجددًا إذا تغيّرت كلمات المرور أو حساب Windows أو الكمبيوتر. أسماء الحسابات داخل الملف ليست مشفرة.

تنقل أداة الإعداد نقطة التقدم السابقة إلى المجلد المحلي إذا لم توجد نقطة تقدم تلقائية بالفعل، حتى تكمل من آخر مزامنة. لتوقيف المزامنة وتعطيل التشغيل التلقائي افتح `tools/stop_hikvision_autostart.cmd`؛ يحتفظ ببيانات الإعداد ونقطة التقدم. إعادة تشغيل الإعداد تُفعّلها من جديد. لم يُسجل المطور مهمة أو يحفظ بياناتك أثناء التطوير؛ هذه الإجراءات تحدث عند تشغيل ملف الإعداد لديك.

## قواعد التجربة

### تشخيص تكرار SYNC FAILED

افتح `tools/diagnose_hikvision_sync.cmd` من حساب Windows الذي أعدّ المزامنة.
يستخدم بيانات الخدمة المحفوظة والمشفرة لقراءة أحداث آخر خمس دقائق وفحص دخول
ERP وصلاحية HR/admin وظهور خدمة الاستيراد. لا يكتب حضورًا ولا يغيّر نقطة التقدم
أو مهمة Windows. لا تعرض الأداة كلمات المرور أو رموز الدخول أو تفاصيل الموظفين.

رسائل الفشل الجديدة تعرض `stage` و`reason` ورقم HTTP وكودًا معتمدًا فقط، دون
عرض نص خطأ مزود الخدمة الذي قد يحتوي على بيانات خاصة. الملف القديم المفتوح
يحتاج إيقافه وتشغيله مجددًا لتحميل التعديل؛ تحديث الملفات وحده لا يغيّر العملية
الجارية. لا تحذف checkpoint: يحتفظ بالتاريخ الذي يجب استكماله بعد التعافي.

- `device_read / device_unreachable`: راجع طاقة الجهاز وعنوانه والشبكة المحلية.
- `device_login_rejected`: أعد الإعداد ببيانات جهاز البصمة الصحيحة.
- `erp_login_rejected`: أعد الإعداد بكلمة مرور HR/admin الحالية، خاصة بعد تغييرها.
- `erp_role_not_allowed`: حساب المزامنة يجب أن يكون HR أو admin نشطًا.
- `attendance_sql_missing`: راجع تثبيت SQL على مشروع Supabase الصحيح.
- `device_events_rejected`: راجع وقت الجهاز والمنطقة الزمنية وصيغة الحدث.
- `checkpoint_save_failed`: راجع المساحة وصلاحيات مجلد التقدم دون حذف الملف.

- تحفظ الأحداث الخام حسب الشركة والجهاز ورقم الحدث وتوقيته، بدون اسم الجهاز الشخصي أو صور الوجه أو بيانات البطاقة. أرقام الموظفين نصوص تحافظ على الأصفار الأولى.
- يحول الخادم فقط `checkIn` و`checkOut` الصريحين. الأحداث الأخرى محفوظة دون استنتاج اتجاهها أو احتساب أوفر تايم. الموظف غير المربوط يبقى حدثه الخام محفوظًا، ويعاد فحص الأيام الثلاثة الأخيرة في الدفعات اللاحقة.
- يوم العمل حسب توقيت الرياض: أول دخول في اليوم وآخر خروج بعده خلال 18 ساعة، مع دعم منتصف الليل، وعدم سحب خروج بعد دخول اليوم التالي. هذه قاعدة تجربة وليست نظام ورديات؛ يلزم تحديد الوردية قبل اعتماد الحساب النهائي للدوام.
- لا يعدّل أيام CSV الموجودة أو الأيام اليدوية. يعدّل فقط سجله الذي أنشأه، إذا ظل مطابقًا لآخر نسخة محفوظة ولم يوجد طلب تصحيح عليه. لا يحسب تأخيرًا أو غيابًا أو راتبًا.
- أول تشغيل يبدأ بآخر 24 ساعة. نقطة التقدم محفوظة في `build/hikvision-sync/checkpoint.txt` بعد نجاح كل الصفحات والدفعات. يعيد قراءة عشر دقائق لمنع فقد الأحداث مع منع التكرار بالخادم. بعد انقطاع طويل يلحق الأحداث على نوافذ يومية. لا تحذف ملف نقطة التقدم أثناء التشغيل.
- لا تعرض جهاز الشبكة الداخلية على الإنترنت. تنفيذ `SQL` وتفعيل الأداة خطوتان محليتان عندك؛ لم يتغير الجهاز أو Supabase تلقائيًا.

مرجع حقول بحث الأحداث: [Hikvision T&A integration](https://www.hikvisioneurope.com/za/portal/portal/02-Technical%20Materials/04-Training%20materials/03-HIK-League%202022/Technical%28Thursday%29/20220526%20Hikvision%20T%26A%20integrate%20solution/20220526%20Hikvision%20T%26A%20integrate%20solution.pdf). دعم الحقول الفعلي يعتمد على استجابة الجهاز المثبت، لذلك المعاينة ترفض غياب حالة اكتمال البحث أو عدم تقدم الصفحات.
