# شاشة حضوري وتجهيز قاعدة البيانات

## ما تم تنفيذه

واجهة جديدة للموظف العادي بنفس الهوية البنفسجية: التنقل بين الأشهر، عدد أيام السجلات والتأخير والغياب المسجلين، مجموع المدد المكتملة، سجل اليوم، البحث بالتاريخ والملاحظات، فلترة الحالة، صفحات الجدول، وبطاقات للشاشات الصغيرة.

الأوقات تُعرض بتوقيت جهاز المستخدم. مدة الحضور هي الفرق بين التوقيتين المسجلين، ولا تمثل حساب ساعات الرواتب أو الإضافي. لا يُفترض أن اليوم الذي بلا سجل يوم غياب. مدة السجل الناقص أو ذو ترتيب أوقات غير صحيح لا تدخل الإجمالي. تُدمج الفترات المتداخلة عند حساب الإجمالي كي لا تُعدّ الدقائق نفسها مرتين. السجلات المتعددة ذات المعرفات المختلفة تُعرض كما هي؛ فحص SQL يكشف الأيام ذات السجلات المتعددة قبل اعتماد ملخصها في الرواتب.

طلب التصحيح يحتاج تاريخ ووقت الحضور والانصراف وسببًا، ويُرسل للمسار الحالي: مدير مرتبط نشط إن وجد، ثم الموارد البشرية، ثم الإدارة. بعد الإرسال يظهر قيد المراجعة ولا تُغيّر مواعيد الحضور مباشرة. إصلاح مسار الموافقات يؤجل تطبيق مواعيد التصحيح إلى اعتماد الإدارة النهائي. التصحيح لا يعيد حساب حالة التأخير من مواعيد وردية مفترضة.

## تطبيق SQL مرة واحدة

1. افتح مشروع ERP الصحيح في Supabase ثم SQL Editor.
2. شغّل `supabase/inspect_employee_attendance.sql` أولًا. يكشف أعمدة الجداول وسياسات RLS والسجلات المكررة والأوقات غير الصحيحة؛ لا يعدّل بيانات.
3. شغّل **محتوى `supabase/install_employee_attendance.sql` كاملًا مرة واحدة**. يعتمد على جداول attendance_records وapproval_requests وusers وemployees وdepartments وحقول workflow وmanager_id الموجودة بالمشروع.
4. اعمل Hot Restart للتطبيق وافتح «حضوري» بحساب موظف مرتبط.
5. اختياريًا شغّل `supabase/verify_employee_attendance.sql` للتحقق من RPC في قاعدة البيانات. يحتاج موظف اختبار له سجل حضور؛ جميع كتاباته داخل معاملة تنتهي بـROLLBACK.

ملف التثبيت يضيف فهارس ووظيفتين فقط: قراءة شهر حساب الموظف وإرسال طلب تصحيح. الوظائف تحدد الموظف والشركة من auth.uid، تتحقق من الحساب النشط وملكية السجل، وتقفل الطلبات المتزامنة لنفس السجل كي تعيد المحاولة معرف الطلب المعلق ذاته. SECURITY DEFINER له search_path فارغ، وإذن التنفيذ للمستخدم المصادق فقط؛ التحقق من الدور والملكية داخل الوظيفة. [مرجع وظائف Supabase](https://supabase.com/docs/guides/database/functions).

الملف لا يحذف أو يعيد كتابة بيانات قديمة، ولا يستبدل سياسات RLS الحالية. إذا كشف فحص RLS جدولًا غير محمي أو سياسات واسعة، يلزم ضبطها قبل ربط أي خدمة خارجية؛ حماية RPC لا تحمي طلبات الوصول المباشر للجداول. [مرجع RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html).

**لم يُطبق SQL على Supabase من هذه الجلسة، ولم تُشغّل اختبارات SQL على PostgreSQL.** لا توجد هنا وصلة إدارة قاعدة البيانات أو نسخة PostgreSQL محلية. قبل التثبيت تعمل قراءة السجلات الحالية عبر المستودع المتوافق، ويظهر أن التصحيح غير متاح. لا تُستخدم كتابة بديلة غير محققة عند غياب RPC. أخطاء الصلاحيات لا تتحول إلى مسار القراءة البديل.

## الملفات

- `lib/core/di/app_di.dart`: تسجيل مستودع حضور الموظف.
- `lib/features/attendance/domain/repos/employee_attendance_repo.dart`: عقد الشهر وطلب التصحيح.
- `lib/features/attendance/data/repos/employee_attendance_repo_impl.dart`: اتصال RPC وقراءة متوافقة عند غياب وظيفة الشهر فقط.
- `lib/features/employee_portal/view/cubit/employee_attendance_cubit.dart`: حالة الشهر، الملخصات، منع الردود القديمة والطلبات المكررة.
- `lib/features/employee_portal/view/widgets/employee_attendance_view.dart`: التصميم المتجاوب.
- `lib/features/employee_portal/view/widgets/employee_attendance_correction_dialog.dart`: نموذج التصحيح.
- `lib/features/employee_portal/view/pages/employee_portal_page.dart`: ربط حضوري للموظف بالواجهة الجديدة.
- `lib/features/approvals/data/repos/approvals_repo_actions_part.dart`: تطبيق التصحيح عند اكتمال الموافقات فقط.
- `test/employee_attendance_test.dart` و`test/employee_attendance_repo_test.dart`: اختبارات الواجهة والحالة والمستودع ومسار الموافقات باستخدام خادم HTTP محلي وهمي، دون بيانات أو حسابات حقيقية.
- ملفات SQL الثلاثة المذكورة أعلاه، وهذا التقرير و`docs/hikvision_attendance_integration.md`.

## التحقق

نجحت مجموعة اختبارات المشروع كاملة: **150 اختبارًا**، بينها اختبارات الحضور الـ27، منها 20 للواجهة والحالة و7 للمستودع والاعتماد. المعاينة المحلية `build/employee_attendance_preview.png` روجعت بصريًا ببيانات اختبار. تدعم الاختبارات العربية والإنجليزية وعروض 320 و768 و1024 و1440، مع تكبير 150% على الموبايل. `flutter analyze` سجل 27 ملاحظة سابقة خارج الملفات الجديدة دون أخطاء جديدة.
