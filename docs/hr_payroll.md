# دورة مسير الرواتب

## ترتيب الشاشات

1. الموارد البشرية تفتح **الرواتب** فتظهر شاشة التجهيز مباشرة، وتحدد الفترة. افتراضيًا من أول الشهر الحالي إلى آخره. زر الساعة أعلى الصفحة يفتح المسيرات السابقة.
2. فتح الصفحة يعرض معاينة فقط، بدون كتابة في قاعدة البيانات. **حفظ كمسودة** ينشئ المسير ويحفظ مبالغه. تشمل المعاينة الموظفين النشطين والأساسي وبدل السكن والنقل والبدلات الأخرى من بيانات التعويضات الحالية.
3. الموارد البشرية تراجع المبالغ ثم تختار **إرسال للمراجعة المالية**. تتحول نفس المسودة إلى «بانتظار مدير المحاسبة»؛ لا يُنشأ مسير جديد عند الإرسال.
4. مدير المحاسبة يفتح نفس المسير من قائمة الرواتب ويوافق لإرساله للأدمن، أو يرفض مع سبب.
5. الأدمن يعتمد نهائيًا أو يرفض مع سبب. الاعتماد ينشئ مهمة صرف لدى مدير المحاسبة.
6. مدير المحاسبة يحول مهمة الصرف لمحاسب، والمحاسب المكلف يسجل بدء الصرف ثم إتمامه.

المدير المباشر خارج دورة الرواتب. الاعتماد لا يعني أن تحويلًا بنكيًا حدث؛ «تم الصرف» تسجيل حالة بعد تنفيذ الصرف الفعلي.

## ما يظهر في التصميم

- شاشة التجهيز: فترة المسير، أسماء الموظفين وصورهم أو الحروف، المسميات الوظيفية، مكونات الراتب وإجمالياتها.
- شاشة المراجعة: معلومات المسير، إجمالي الأساسي والبدلات، سجل تواريخ الإعداد والإرسال والاعتمادات المتاحة، تفاصيل الموظفين، والإجراء الذي تسمح به حالة المسير ودور المستخدم.
- زر حفظ المسودة يحفظ فعليًا عند أول ضغطة. الضغط مرة أخرى أو إعادة محاولة الإرسال يستخدم نفس المسير المحفوظ. الفترة تُقفل بعد الحفظ، ويمكن الرجوع للمسيرات السابقة وفتح المسودة بنفس قالب التجهيز.
- تصدير CSV يدعم الأسماء العربية باستخدام UTF-8.

## حدود البيانات الحالية

النظام الحالي يولّد الأساسي والبدلات فقط، ولا يحتسب الخصومات أو الأوفر تايم أو الاستقطاعات أو الراتب النسبي حسب أيام العمل. لا نعرض أرقامًا افتراضية لهذه البنود، ولا نستخدم أرقام الصور التجريبية.

تحديد الفترة لا يحول الحضور إلى خصومات تلقائية. المبالغ نسخة محفوظة عند الإنشاء وليست حقولًا قابلة للتعديل في الشاشة الحالية؛ تعديل تعويض الموظف لاحقًا لا يحدث المسير السابق تلقائيًا. إعادة الإرسال لمسير مرفوض ترسل نفس مبالغه، فلا تستخدمها باعتبارها إعادة حساب.

الأفضل إبقاء التجهيز والمراجعة مرحلتين على نفس المسير، وتأجيل احتساب المتغيرات إلى خطوة منفصلة بقواعد معتمدة قبل اعتماد الرواتب للتشغيل المالي الكامل. سجل المعروض هو تواريخ المراحل الموجودة في المسير، وليس سجل تدقيق كاملًا لكل رفض أو إعادة إرسال.

تستخدم الشاشات جداول ودورة الرواتب الموجودة؛ لم يتم تشغيل SQL أو إنشاء مسير على قاعدة البيانات أثناء التطوير.
